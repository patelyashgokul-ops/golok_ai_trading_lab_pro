# P08 authorization and datasets

Historical dataset creation requires an explicit publisher-specific manual review. The server assigns the review ID. New SmartAPI datasets bind the provider review and receipt basis. Normalized daily datasets retain the file audit, review, calendar, mapping, interval and conservative local receipt time. Migration preserves prior datasets with absent lineage and does not grant new access.

The dataset form shows the current lineage classification. A legacy market dataset without both a bound review and a publication basis has insufficient evidence, even if a grant now exists for a publisher with the same label. Legacy synthetic records remain classified as simulation inputs. The migration verification compares the original review references and publication assertions before and after upgrade and reports aggregate counts. [Controlled migration log](evidence/p08/migration-lineage/upgrade/dataset-lineage.log)

New research and queued research recheck the original review for active company, provider, upstream and descriptive purpose. A later review supersedes the earlier one for that publisher. An administrator can revoke a review directly. The read/search rules on candles, research results, findings and daily audit rows check the bound grant, dates and display rights. Odoo's recursive export path denies top-level and nested exports of market records on the covered models. P08.2 supports ongoing archival, fixed-term storage and transient-only agreements. Transient-only input cannot be saved. Fixed-term storage enforcement blocks reads and new imports after the recorded date. Records and audit history remain intact. Any physical deletion requires an explicit decision under the applicable agreement. Full dataset fingerprints and automatic archival disposition remain open.

**Normalize to Research Datasets** selects effective company NSE mappings and requires exact ISIN agreement. It records an audited relationship and produces daily candles within the session grid. Duplicate requests reuse linked datasets. Receipt is rounded upward to the supported minute.

A source administrator can upload a corrected Legacy or UDiFF file and select **Previous File Revision** for the same source, calendar, session and current review. Enter the publisher reference in **Publisher Correction Reference**. The original audit and multi-session dataset remain intact. Normalization creates separate one-session datasets with an immutable audit link and candle/calendar SHA-256. Exact retries and canonically identical corrections for the same predecessor reuse the accepted revision. A changed file submitted without its predecessor is quarantined. This workflow was tested using authored daily data.

The authorization service evaluates named operations against source capabilities, explicit grants, lifecycle, review evidence and active company. ORM tests exercise rejection of replay, fitting, optimization, scheduled synchronization, prospective paper use, live use, export, redistribution and unknown operations on a source authorized for descriptive research. A manual SmartAPI synchronization uses the historical import scope. Reusing an earlier sync report also requires its bound review to remain effective.

**Generate Deterministic Fixture** creates a reserved synthetic instrument from a completed fixture calendar. Odoo assigns the algorithm version, fixed seed and SHA-256 of the calendar and generated observations. A repeated request returns the original dataset. Ordinary users cannot assign the generated lineage fields or upload new observations into a generated dataset. Existing simulation CSV datasets have no generated-lineage metadata. Neither kind supplies real financial evidence. [Regression tests](../tests/test_lab.py)

**Compare Sources** takes two mapped datasets and one closing timestamp. It checks company, provenance category, instrument, ISIN, venue, interval, opening and closing times and reviewed price and volume semantics. The audit records upstreams, absolute OHLCV differences and one-tick price tolerance with exact volume comparison. A conflict blocks both datasets from future imports, research, experiments and virtual posting. Source revisions can be registered separately. The comparison is operator-triggered and was tested on authored fixtures. Live-provider comparison remains unverified.
